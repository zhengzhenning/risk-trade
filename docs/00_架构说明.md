# 架构说明

**架构风格**：整洁架构（Clean Architecture）+ 端口适配器（Hexagonal）+ DDD 轻量聚合，落地形态为**模块化单体**。

| 范式 | 在本项目的落点 |
| --- | --- |
| 整洁架构 | 四层单向依赖 `interfaces → application → domain ← infrastructure`，靠 `application/ports.py` 倒置 |
| 端口适配器 | 端口在业务层定义，东财/腾讯/文件/PG/渲染均为可替换实现 |
| DDD 轻量 | 聚合根自持不变量；领域服务承载纯规则；不做 CQRS、不引入事件总线 |
| 模块化单体 | 单进程单仓库，按业务域分包，非微服务 |

文档编号：`LEVEL_ORDER_NAME` —— 第 1 位=层级，第 2 位=顺序（从 0 起）。

| 层级 | 文档 |
| --- | --- |
| 0 顶层 | `00_架构说明` |
| 1 设计与分析 | `10_详细设计` · `11_代码链路树` · `12_前端架构` · `13_后端编码规约` · `14_前端编码规约` |
| 2 整体领域 | `20_整体领域设计` |
| 3 业务模块 | `30_业务蓝图` 索引 + `business/30_…36_/`（每模块「领域设计 + 详细设计」） |

A 股每日看板：**采集行情 → 固化快照 → 按日动态渲染**。数据只有一个源（快照库），页面按需生成，不存 HTML。

状态：P1 完成（四层 + 5 个端口 + 本地组合根，可每日构建快照并渲染）；P2（PG/Redis/FastAPI）待接入。

## 0. 前后端全景

```text
H5(uni-app/Vite) ──┐
小程序(uni-app) ───┼─ HTTP / SSE·WS ─▶ Caddy ─▶ FastAPI
APP(uni-app) ──────┘                              │
                                       application 用例（端口）
                                                  │
                                  domain 聚合 + 领域服务
                                                  │
                                  infrastructure（行情/存储/渲染）
                                                  │
                                   PostgreSQL · Redis · 东财/腾讯
```

- 前端 monorepo `web/`，与后端只通过 HTTP 与 SSE/WS 契约耦合。
- 后端分四层，端口在 `application/ports.py`，实现放 `infrastructure/`。
- 静态页（现有 `archives/*.html`）作为过渡形态并存，迁完即下线。

## 1. 分层

```text
interfaces     入口层   HTTP / SSE / Cron / CLI   只解析协议、组装依赖
      ↓
application    业务层   BuildView · BuildSnapshot · ports   只编排，定义端口
      ↓
domain         领域层   aggregates（聚合）+ services（纯规则）  零外部依赖
      ↑
infrastructure 数据层   行情源 / 存储 / 渲染      实现端口，被组装
```

依赖只向内：`drivers → adapters → core`。反向引用被 `tests/test_architecture.py` 与 `import-linter` 拦截。

## 2. 数据流

### 2.1 写路径（Cron / CLI 驱动）

```text
外部源（东财/腾讯/新闻）
        │ HTTP
        ▼
  Adapter（解析为实体）
        │ Stock / Bar / Alert
        ▼
  Use Case（BuildSnapshot）
        │ 幂等键 (day) → rev+1
        ▼
  SnapshotRepo ──▶ 快照库（P1 文件 / P2 PostgreSQL）
        │
        └──▶ 失效页面缓存（P2 Redis）
```

### 2.2 读路径（HTTP 驱动）

```text
浏览器 ──GET /d/2026-11-12──▶ API（P2 FastAPI）
                                  │
                                  ├─ 缓存命中 ──▶ 返回 HTML
                                  │
                                  └─ 未命中 ──▶ BuildView(day)
                                                   │
                                     SnapshotRepo.load(day)
                                                   │
                                              Renderer → HTML
```

### 2.3 实时流（60s）

```text
Scheduler ──每 60s──▶ RefreshLive ──▶ QuotePort（东财→腾讯兜底）
                                            │
                                            ├─▶ live 表（最新值）
                                            └─▶ SSE 推送 / 或前端轮询 live.json
```

三条流的共同点：**外部数据只进快照，页面只读快照**。

### 3.1 分层契约

| 层 | 可以依赖 | 禁止依赖 | 职责 |
| --- | --- | --- | --- |
| domain | 仅标准库 | 任何其他层、IO、日志 | 聚合不变量与纯规则 |
| application | domain | infrastructure、interfaces | 编排用例、定义端口 |
| infrastructure | domain、application.ports | interfaces | 协议转换与持久化 |
| interfaces | application、infrastructure | — | 参数解析、依赖组装 |

违规由 `tests/test_architecture.py` 与 `import-linter` 双重拦截；编码与提交约束见仓库根 [AGENTS.md](../AGENTS.md)。

## 5. 如何编码

### 新增一个用例

1. 在 `application/usecases/` 建文件，构造函数注入所需 **端口**，不要 import 任何实现。
2. 只操作 `domain/aggregates/` 的聚合；第三方字段不要出现在这里。
3. 在 `tests/` 加一条用 Fake 端口的测试。
4. 需要定时执行时，在 `interfaces/scheduler.py` 的 `JOBS` 加一条（含 cron 与用例名）。

```python
class RefreshLive:
    def __init__(self, quotes, repo) -> None:
        self._quotes = quotes
        self._repo = repo

    def __call__(self, codes: list[str]):
        return self._quotes.snapshot(codes)
```

### 新增一个数据源

1. 在 `infrastructure/` 建文件，实现已有端口方法（如 `snapshot`）。
2. 把第三方格式（JSONP、`~` 分隔）解析在本文件内，返回领域聚合。
3. 需要容灾时用 `fallback.py` 组合，不改调用方。
4. 端点联调：`PYTHONPATH=src python3 -c "from ... import X; print(X().snapshot(['002578']))"`

### 约定

| 项 | 规则 |
|---|---|
| 命名 | 适配器 `XxxAdapter`，用例 `Xxx`（动词开头），端口 `XxxPort` |
| 错误 | 适配器吞掉单条失败并跳过；用例失败抛异常，由驱动层记录 `job_run` |
| 时间 | 一律 `datetime.date`，字符串只出现在存储与渲染边界 |
| 幂等 | 同一 `day` 重跑只增 `revision`，不改历史行 |
| 测试 | `core` 覆盖率必须靠 Fake 端口跑通；适配器只做冒烟 |

## 6. 任务表

| Job | 频率 | 用例 | 幂等键 | 失败处理 |
|---|---|---|---|---|
| refresh_live | 60s（交易时段） | RefreshLive | (code, ts) | 退避重试，记 job_run |
| build_snapshot | 交易日 15:08 | BuildSnapshot | (day) → rev+1 | 重试 3 次后告警 |
| judge_wyckoff | 交易日 15:05 | JudgeWyckoff | (day, code) | 跳过失败标的 |
| fetch_news | 08:30 / 11:35 / 15:06 | AttributeNews | (day, url) | 单渠道失败降级 |

## 7. 规则（硬约束）

1. `core` 不 import 框架、驱动、数据库。
2. 第三方响应结构只允许出现在 `adapters`。
3. 快照不可变，只加 `revision`。
4. 页面不落盘，只有缓存。
5. 任务必须注册，禁止用例内自循环。
6. 判断需可复现：规则版本与 prompt 版本随快照入库。

## 8. 排障

| 现象 | 原因 | 处置 |
|---|---|---|
| 行情为空 | 东财 push2 断连 | 用 `FallbackQuotes` 自动走腾讯；确认适配器返回非空 |
| 依赖方向报错 | 内圈引了外圈 | 按报错文件改注入，不要 `import adapters` |
| 同日重复构建 | 缺幂等键 | 检查 `BuildSnapshot` 的 `rev` 逻辑 |
