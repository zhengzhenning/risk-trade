# 代理池与抓取降级

目标：用青果代理降低限流概率，同时保证 3 分钟 IP 存活期只消耗 1 个 IP；API 失败后降级网页抓取。

## 一、分层

```text
domain/services/rate_limit  令牌桶与坏 IP 判定（纯规则，待补）
application/ports           ProxyPort（acquire / report_bad）
infrastructure/qingguo_proxy 青果适配器：进程内单租约复用
infrastructure/proxy_client  重试 → 退避 → 连续失败才换 IP → 网页抓取
interfaces/composition      装配到行情/K线/板块适配器，全进程共用一个池
```

## 二、租约规则

| 规则 | 取值 |
| --- | --- |
| IP 存活 | 180 秒（青果口径） |
| 租约复用上限 | 120 秒（`settings.json` 的 `session_ttl_seconds`），小于 IP 存活 180 秒 |
| 复用粒度 | 每进程 1 个池（`composition` 单例）、每线程 1 个客户端，全部任务共用同一租约 |
| 坏 IP 判定 | 同一线程连续失败 2 次才标记，冷却 600 秒后自动过期 |
| 采集时段 | 9:15–11:30、13:00–15:05；午休与收盘不采集 |
| 密钥 | 只存于 gitignore 的 `config/settings.json`，禁止入库与日志 |

## 三、失败处理顺序

```text
1. 缓存命中           → 直接返回
2. 同 IP 退避重试     → 0.5s / 1s（默认 2 次）
3. 连续失败 2 次 → 标记坏 IP，换租约重试一次（单次取数最多换 1 个）
4. 仍失败 → 降级网页抓取（scraper）
5. 仍失败 → 抛错并计入 failures 指标
```

## 四、代码位置

- `infrastructure/qingguo_proxy.py`：`QingguoProxyPool.acquire()` / `report_bad()`
- `infrastructure/proxy_client.py`：`ProxyHttpClient.get()` / `get_or_scrape()`
- `tests/test_proxy.py`：租约复用、过期轮换、坏 IP、缺密钥、重试、网页降级

## 五、启用方式

青果凭据已从本地配置移除，当前 `proxy.enabled=false`，全部请求直连。后续替换供应商时：

1. 在 `config/settings.json`（已 gitignore）填 `provider`、`key`、`password`，并把 `enabled` 置 `true`；
2. 若新供应商返回格式不同，替换 `infrastructure/qingguo_proxy.py` 的 `_EXTRACT` 与 `_server_of`；
3. 重启 API、快照循环与采集调度三个进程。

未启用或缺少密钥时 `acquire()` 返回 None，客户端直连。

## 六、网页抓取降级

`get_or_scrape(url, scraper)` 在 API 三次尝试后调用 `scraper`。当前只提供接口与单测，
具体解析器（东财行情页 / 腾讯 quote 页面）按目标字段逐个实现，标注「拟定」。

## 七、待确认

- 青果提取接口路径与返回格式需按其文档核对（代码中为可替换的 `_EXTRACT`）。
- 代理延迟对实时行情的影响未实测。

## 八、消耗口径

- 正常情况：每个进程每 120 秒最多提取 1 个 IP，即约 30 个/小时；调度、快照、API 三个进程合计约 90 个/小时上限。
- 2026-11-19 实测：修复前 09:15–15:17 消耗 3,831 个（约 640 个/小时），主因是 28% 的失败轮换率叠加每次采集新建代理池。
- 异常情况：同一线程连续失败 2 次才会换 IP，且冷却期内的 IP 不会重复提取；日志 `proxy stats ... extracts=` 可直接看出每客户端累计提取数。
